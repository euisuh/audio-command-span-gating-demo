# Audio command-span gating demo

A small, runnable demonstration of one defensive idea for voice agents, built on synthetic speech. It is a demonstration of ideas that already exist in the literature. It makes no novelty claim and no claim about any deployed system.

## What the demo shows

Setup: a voice agent receives audio in which a genuinely watermarked command ("Please turn lights on.") is followed by, or has inserted next to it, an unmarked command ("Please open door."). Actions are only entries in a local JSON log; nothing is executed.

- Utterance-level gate: accepts the whole clip if it carries a valid AudioSeal mark. The unmarked adjacent command goes through in 60/60 mixed clips.
- Word-span gate: joins ASR word timestamps (faster-whisper) with AudioSeal's sample-level localization and only acts on words whose span is marked. The unmarked command is blocked in 0/60 mixed clips, and the genuine command still completes in 60/60 benign clips (0 points of benign loss).
- Signed original-chunk gate (a stronger baseline that uses authenticated packet boundaries, Ed25519): also 0/60 and 60/60. It ties the word-span gate, so this demo shows no advantage over it.

Source for every number above: [results/summary.json](results/summary.json) (arms table), [results/pairs.jsonl](results/pairs.jsonl) (per-pair raw outcomes).

## What it is not

- The 100-point gap between the utterance gate and the word-span gate is largely by construction. The extra command is fixed, unmarked synthetic audio placed at a fixed phrase boundary, and the utterance gate is defined to look at one clip-level verdict. The gap measures what each gate is defined to check, not a vulnerability found against a real system. No adaptive attacker, removal, transplantation, forging, or detector optimisation was tried ([docs/PROTOCOL.md](docs/PROTOCOL.md), Scope section).
- Scope is synthetic text-to-speech with preset Kokoro voices, a fixed set of ten enumerated commands, and a simple exact-word-sequence parser. Distinct voice presets are not verified distinct human speakers. No real speakers, no microphone or loudspeaker capture, no codecs ([docs/PROTOCOL.md](docs/PROTOCOL.md); original risk notes in [docs/NOVELTY.md](docs/NOVELTY.md)).
- "Authorized" means the clip carries one enrolled 16-bit AudioSeal message. This assumes an attacker cannot use the embedder; public AudioSeal marks are not cryptographic speaker authentication ([docs/NOVELTY.md](docs/NOVELTY.md)).
- The signed baseline uses authenticated transport packets, so it is not a waveform-only defense and is not a reproduction of MerkleSpeech ([docs/PROTOCOL.md](docs/PROTOCOL.md), arms section).
- 60 pairs is small. The zero-harm count has an exact one-sided 95% upper bound of 4.87% under independent trials ([results/summary.json](results/summary.json)).

## Prior art this repeats

The ideas are established. Use these, not this repo, as the references:

- AudioSeal, sample-level localized watermark detection with a 16-bit message: [arXiv 2401.17264](https://arxiv.org/abs/2401.17264), code [facebookresearch/audioseal](https://github.com/facebookresearch/audioseal).
- MerkleSpeech, signed chunk commitments and splice-aware provenance: [arXiv 2602.10166](https://arxiv.org/abs/2602.10166).
- SpeechVerifier, speech tampering and splicing detection with embedded fingerprints: [arXiv 2505.23821](https://arxiv.org/abs/2505.23821).
- PartialSpoof, utterance and segment-level detection of partially fake audio: [github.com/nii-yamagishilab/PartialSpoof](https://github.com/nii-yamagishilab/PartialSpoof).
- Luong et al., threshold-dependent partial-fake localization and out-of-domain behavior: [arXiv 2507.03468](https://arxiv.org/abs/2507.03468).
- Voice-command injection and defense: [Roy et al., NSDI 2018](https://www.usenix.org/conference/nsdi18/presentation/roy).

The novelty read written when the pilot was run is [docs/NOVELTY.md](docs/NOVELTY.md), with the twelve dated searches in [docs/search-log.json](docs/search-log.json). It rates the idea partly occupied and global novelty unverified. A search found no identical experiment, which is a bounded observation, not proof of absence.

## Results (full run, 21.3 minutes on CPU)

Source: [results/summary.json](results/summary.json), regenerated by `python summarize.py --dir results`. Run time from [results/run-complete.json](results/run-complete.json).

| Arm | Unauthorized actions, 60 mixed clips | Authorized command completed, 60 benign clips |
|---|---:|---:|
| No gate | 60/60 | 60/60 |
| Utterance gate | 60/60 | 60/60 |
| Word-span gate | 0/60 | 60/60 |
| Signed original chunks | 0/60 | 60/60 |

30 pairs append the extra command and 30 insert it at a phrase boundary; both strata show the same pattern. Intervals are degenerate at 0 or 100 and say little; use the 4.87% bound above.

Null (no-watermark) clips, voices disjoint from the pairs ([results/summary.json](results/summary.json), `audit` and `calibration_*` keys; raw rows in [results/audit.jsonl](results/audit.jsonl) and [results/calibration.jsonl](results/calibration.jsonl)):

| Measure on 300 unmarked audit clips | False accepts |
|---|---:|
| Score-only clip admission (threshold set for 1% on 100 calibration clips) | 1/300 |
| Score-only, any word admitted | 18/300 (6.00%) |
| Exact enrolled-message required, clip level | 0/300 |
| Exact enrolled-message required, word level | 0/300 |
| Parser actions after word-span gating | 0/300 |

So score-only span localization calibrated at 1% did not hold 1% on unseen voices, while requiring the exact enrolled message did. The 0/300 has a one-sided 95% upper bound of 0.994% under independent trials ([results/summary.json](results/summary.json)).

Timing diagnostic: AudioSeal watermark on/off transitions land a mean of 109.8 ms from the true splice points (95% interval 94.3 to 127.0), 90/90 matched within 500 ms. Nearest-transition matching is optimistic and this is not hand-labeled word-boundary accuracy ([results/summary.json](results/summary.json), `boundary_*` keys; definition in [docs/PROTOCOL.md](docs/PROTOCOL.md)).

The original pilot's frozen decision rule labelled this "GO, conditional synthetic prototype, no demonstrated advantage over signed chunks" ([results/summary.json](results/summary.json), `verdict`). That label is about the pilot's own thresholds, not about novelty or deployment.

## Reproduce

Needs about 3 GB of disk for the venv, weights and cache, and network access for the first run.

```sh
python3.14 -m venv .venv
.venv/bin/pip install -r requirements.txt
./fetch_kokoro.sh                      # Kokoro files into cache/tts, SHA-256 checked

.venv/bin/python pilot.py --selfcheck  # unit checks, no models
```

Reduced run, 5 pairs, reusing the shipped thresholds (about 1 minute after downloads; AudioSeal and Whisper tiny weights download on first use into `cache/`):

```sh
.venv/bin/python pilot.py --pairs 5 --thresholds results/thresholds.json
.venv/bin/python summarize.py
```

Full run, 100 calibration clips, 300 audit clips, 60 pairs (about 21 minutes in the original run):

```sh
.venv/bin/python pilot.py
.venv/bin/python summarize.py
```

Outputs go to `out/` and the scripts refuse to overwrite it; delete `out/` to rerun. To recheck the shipped numbers without any models: `.venv/bin/python summarize.py --dir results` (rewrites `results/summary.json`; `git diff` should show no change).

Expected output of the reduced run, from a fresh venv:

```
no_gate        unauthorized (mixed clips) 5/5   benign completion 5/5
utterance      unauthorized (mixed clips) 5/5   benign completion 5/5
word_span      unauthorized (mixed clips) 0/5   benign completion 5/5
signed_chunks  unauthorized (mixed clips) 0/5   benign completion 5/5
```

The summary also prints `"verdict": "REVISE"` for a reduced run; the GO/KILL rule only applies to the full allocation. The five pairs are the first five entries of `pairs` in `allocation.json` (P022, P053, P043, P050, P055). In the author's test run their ASR words and `probabilities_sha256` values equalled the rows with the same `id` in `results/pairs.jsonl`; you can compare them yourself.

## Layout

- `pilot.py` runs calibration, audit and pair evaluation; `runtime.py` holds model loading and CPU settings; `allocation.py` / `allocation.json` define every text, voice, speed and pair (seed 20261002); `summarize.py` computes the table and bootstrap intervals (5,000 resamples over pairs).
- `results/` holds raw per-clip outputs and the summary of the one full run.
- `docs/PROTOCOL.md` and `docs/NOVELTY.md` are the original preregistration and novelty text. They mention file names of the original project (`freeze.json`, `sources/`) that are not in this repo.

## Known caveat in the setup

espeak-ng, used by Kokoro for phonemes, crashed here when the venv sat under a very long path (194 characters; 159 worked). `runtime.py` works around it by running from a short copy under `/tmp` when the path is long.
